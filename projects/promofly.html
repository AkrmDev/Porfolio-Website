Overview Problem Role Architecture Stack Challenges Results

Overview

Promofly consolidates multi-network posting into a single web app so creators can plan content, schedule ahead, and publish without switching between separate social tools.

Problem

Social workflows are fragmented across separate logins, caption formats, and schedulers. Teams need authentication, storage, API publishing, and a single coherent interface in one product.

My role

Designing and implementing the full stack: React client for navigation and publishing flows, Firebase for auth and persistence, Node/Express services for outbound platform APIs, and iterative product work toward scheduling and multi-network publish.

Architecture

Browser client talks to Firebase for identity and stored content state. Server routes wrap third-party social APIs so tokens and publish calls stay off the client where possible. The hosted build on Firebase Hosting is the current deployment surface while features land incrementally.

Tech stack

  • React
  • Firebase Auth & storage
  • Node.js
  • Express
  • Twitter / platform APIs

Technical challenges & solutions

  • Multi-platform APIs: normalize auth and publish flows behind server routes instead of hard-coding each network into the UI.
  • Auth + persistence: Firebase for signup/login and durable user data without standing up a custom auth service first.
  • Incremental delivery: ship a live build while scheduling, captions, and analytics continue to expand.

Results

Delivered a working full-stack foundation with authenticated users, a React application interface, Firebase backend services, and API-backed publishing paths. Additional features remain in progress.
